Ejercicios para practicar C

Cómo usar estos ejercicios

Cada ejercicio es un programa completo e independiente: no necesitas el código del trazador de rayos. Están agrupados por tema y repasan lo visto en las tareas. También incluyen las partes importantes de C que el proyecto no llegó a necesitar: cadenas, entrada por teclado, argc/argv, ficheros, union, listas enlazadas, operadores de bits, funciones variádicas y depuración. Esos ejercicios llevan la etiqueta Nuevo; antes de empezarlos, busca en la documentación las funciones que se citan (man 3 fgets, por ejemplo).

La dificultad va de ●○○ (calentamiento) a ●●● (pequeño proyecto). Las pistas están plegadas: intenta el ejercicio antes de abrirlas.

Normas para todos los ejercicios

  • Compila siempre con avisos: gcc -std=c11 -Wall -Wextra -g ej.c -o ej -lm. Un ejercicio no está terminado mientras salga algún aviso.
  • Si usas memoria dinámica, comprueba que no hay fugas con valgrind ./ej o compilando con -fsanitize=address,undefined.
  • Comprueba siempre lo que puede fallar: el valor de retorno de malloc, fopen, scanf…
  • Como en el curso: identificadores en inglés, comentarios en español.

E2

La conjetura de Collatz

●○○

Dado un entero positivo n: si es par, divídelo entre 2; si es impar, sustitúyelo por 3n+1. Se conjetura que siempre se llega a 1. Escribe:

  1. Una función int collatz_steps(long n) que devuelva cuántos pasos hacen falta para llegar a 1.
  2. Un main que busque, entre 1 y N−1, el número con la secuencia más larga.
resultados para comprobar
collatz_steps(27) = 111
N = 10       -> el número 9 necesita 19 pasos
N = 1000000  -> el número 837799 necesita 524 pasos
Pista

Los valores intermedios crecen mucho más que n: con int de 32 bits puedes desbordar. Por eso se pide long. El cuerpo del bucle cabe en una línea con el operador ternario: n = (n % 2) ? 3*n + 1 : n / 2;

●○○Nuevo

  1. Imprime el sizeof de char, short, int, long, long long, float, double y void * (usa %zu).
  2. Imprime INT_MIN, INT_MAX, UINT_MAX y DBL_EPSILON.
  3. Guarda 0 en una variable unsigned int y réstale 1. ¿Qué sale? ¿Por qué?
  4. Calcula tú mismo el épsilon de máquina: empieza con eps = 1.0 y divide entre 2 mientras 1.0 + eps/2 != 1.0. Compáralo con DBL_EPSILON.

resultados típicos en Linux de 64 bits

E4

Adivina el número

●●○Nuevo
scanfdo … whilerandsrand(time(NULL))

El programa elige un número secreto entre 1 y 100 y el usuario intenta adivinarlo. Tras cada intento responde «mayor», «menor» o «¡correcto!», y al final dice cuántos intentos hicieron falta.

  • Usa un bucle do … while: al menos se pide un número.
  • Valida la entrada. scanf devuelve cuántos datos ha leído. Si el usuario escribe hola, avisa y vuelve a pedir el número en lugar de entrar en un bucle infinito. Si devuelve EOF (Ctrl+D), termina.
  • Al acabar, pregunta «¿Otra partida? (s/n)».
terminal
$ ./adivina
Intento: 50
Mayor.
Intento: hola
Eso no es un número.
Intento: 75
Menor.
...
¡Correcto! Lo has adivinado en 6 intentos.
Pista

Cuando scanf("%d", &x) falla, los caracteres erróneos se quedan en la entrada. Hay que descartarlos antes de reintentar: while ((c = getchar()) != '\n' && c != EOF) ; Para leer la respuesta s/n usa scanf(" %c", &r). El espacio delante de %c se salta los blancos pendientes.

Ampliación: invierte los papeles. Tú piensas el número y el programa lo adivina con búsqueda binaria. ¿Cuántos intentos necesita como máximo?

E10

Estadística con aritmética de punteros

●●○Nuevo

Escribe estas funciones. Ninguna puede usar la notación v[i]: recorre el array moviendo un puntero desde v hasta v + n.

En main, usa un array de medidas (por ejemplo, diez periodos de un péndulo). Imprime los resultados y la posición de un valor encontrado con find, calculada como p - v.

Pista

v[i] es exactamente *(v + i). Un bucle típico es for (const double *p = v; p < v + n; p++) suma += *p;. Para invertir: double *ini = v, *fin = v + n - 1; y avanza ambos hasta que se crucen. ¿Por qué find devuelve const double *?

Matrices: estáticas y dinámicas

●●○Nuevo

  2. Ahora con tamaño leído en tiempo de ejecución, implementa la matriz de dos formas:
    • (a) double **: un array de punteros a filas, cada fila con su propio malloc.

Bloque 4 — Cadenas de caracteres y línea de órdenes

Concepto de C · qué es una cadena

En C no existe un tipo «cadena». Una cadena es un array de char terminado por el carácter nulo '\0'. "hola" ocupa 5 bytes. Ninguna función de <string.h> sabe el tamaño del array: todas van leyendo hasta encontrar ese '\0'. Por eso se escribe fuera del array tan fácilmente.

E16

●●○Nuevo

  • tree_free en postorden: ¿por qué tiene que ser postorden?
  • Inserta las palabras de un texto ya ordenado. ¿Qué altura tiene el árbol? ¿Qué le ha pasado?
Pista

Una firma cómoda es node *tree_insert(node *root, const char *word), que devuelve la (posible) nueva raíz: root->left = tree_insert(root->left, word);. Para copiar la palabra, haz malloc(strlen(w) + 1) + strcpy. Ese + 1 es para el '\0'. Cada copia necesitará su propio free.

E28

Dentro de un double: IEEE 754

●●●Nuevo
uint64_tmemcpyunionPRIx64NaN / inf

Un double ocupa 64 bits: 1 de signo, 11 de exponente (con sesgo 1023) y 52 de mantisa. Escribe un programa que, para cada número que reciba por argv, muestre sus bits en hexadecimal, separe los tres campos y reconstruya el valor con la fórmula (−1)s · 1.m · 2e−1023.

salida esperada
$ ./ieee 1 -0.1
1      bits=3ff0000000000000  signo=0  exponente=1023 (2^0)   mantisa=0000000000000
-0.1   bits=bfb999999999999a  signo=1  exponente=1019 (2^-4)  mantisa=999999999999a

Prueba también 0, -0, 1e308*10 (infinito), 0.0/0.0 (NaN) y 5e-324 (el menor número subnormal).

Pista

Copia los bytes con memcpy(&u, &d, sizeof d), siendo u un uint64_t. Esa es la forma correcta; un cast de punteros *(uint64_t *)&d viola las reglas de aliasing. Luego, exponente: (u >> 52) & 0x7FF; mantisa: u & ((1ULL << 52) - 1). Para imprimir: printf("%016" PRIx64, u) con <inttypes.h>.

Bloque 9 — Preprocesador, módulos, funciones variádicas y depuración

E29

Macros: potencia y peligros

●●○

  1. Predice y después comprueba qué imprime este fragmento. Corrige las macros para que den el resultado «esperado». ¿Hay alguno que no se pueda corregir con una macro?

Pista

Una macro sustituye texto antes de compilar; no evalúa nada. Pon paréntesis alrededor de cada parámetro y de toda la expresión: #define SQUARE(x) ((x) * (x)). Aun así, MAX(i++, 2) incrementa i dos veces. Por eso, en C moderno se prefiere una función static inline, como hicimos con vec3.

E31

Funciones con número variable de argumentos

●●○Nuevo
stdarg.hva_listva_argvfprintf

printf acepta cualquier número de argumentos. Tú también puedes escribir funciones así:

  1. double average(int n, ...), que haga la media de n valores double: average(3, 1.0, 2.0, 6.0) → 3.
  2. void log_msg(const char *level, const char *fmt, ...), que añada la hora y el nivel delante del mensaje y lo pase todo a vfprintf(stderr, ...).
  3. Un mini printf propio que solo entienda %d, %s, %c y %%, escribiendo carácter a carácter con putchar.
Pista

Patrón: va_list ap; va_start(ap, n); ... va_arg(ap, double) ... va_end(ap);. La función no puede saber cuántos argumentos ni de qué tipo le han pasado; por eso hace falta n o una cadena de formato. ¿Qué ocurre con average(3, 1, 2, 6), con enteros? Compruébalo y explícalo.
