C · Bloque 1 — Compilar y ejecutar (Tarea 0)

C es un lenguaje compilado: no hay intérprete como en Python. Siempre hay dos pasos: primero el compilador (gcc) traduce tu archivo .c a un ejecutable, y después tú ejecutas ese archivo.

Recuerda

  • Todo programa arranca en la función main.
  • Para usar printf hay que incluir su cabecera: #include <stdio.h>.
  • return 0; es el código de salida que main le da al sistema operativo.
  • Las banderas de gcc: -Wall (todos los avisos, úsalo siempre), -O2 (optimiza), -o nombre (nombra el ejecutable), -lm (enlaza la biblioteca matemática; va al final).

Pista · el ./

Para ejecutar escribimos ./rt, no rt. El ./ significa «el archivo que está aquí, en esta carpeta». Si lo olvidas, la terminal responde «orden no encontrada».

C · Bloque 2 — Tipos numéricos y el molde (double) (Tarea 1)

C distingue números enteros (int) de números reales (double). Esta distinción es la fuente de error número uno para quien empieza.

El molde (cast)

Si divides dos int, C hace división entera y descarta los decimales (3/4 da 0). Escribiendo (double)i conviertes el valor a real antes de dividir, y el resultado ya es 0.75. A eso se le llama molde o cast.

Pista · el retorno de carro \r

En el mensaje de progreso, \r mueve el cursor al inicio de la línea sin bajar, así el contador se sobrescribe en el sitio en vez de imprimir miles de líneas. \n, en cambio, sí baja de línea.

C · Bloque 3 — Bucles, condicionales y booleanos (Tareas 1 y 4)

Recorremos filas y columnas de píxeles con dos bucles for anidados. Para decidir si un rayo toca una esfera usamos un if.

Booleanos «a la C»

C (antes de C99) no tenía tipo booleano. Se usa un int donde 0 es falso y cualquier otro valor es verdadero. Por eso una función como hit_sphere devuelve un int que actúa como «¿golpea?». Existe también <stdbool.h> con bool, true y false para mayor claridad.

for (int i = 0; i < n; i++) if (cond) { ... } == igualdad = asignación <= >= != && (y) || (o)

Ojo

Dentro de un if, == compara y = asigna. if (x = 0) no compara: asigna 0 a x y siempre es falso. Es un error clásico.

C · Bloque 4 — struct, typedef y paso por valor (Tareas 2 y 3)

Un trazador de rayos vive de vectores de 3 componentes (puntos, direcciones, colores RGB). En C++ se usaría una clase con operadores +, *…; en C no hay sobrecarga de operadores, así que definimos un struct y una función por cada operación.

Ideas clave

  • Un struct agrupa varias variables bajo un mismo nombre; accedes a un campo con el punto: a.x.
  • typedef le da un nombre corto al tipo para no escribir struct vec3 cada vez.
  • Nuestras funciones pasan y devuelven vec3 por valor (una copia). Para 3 double es barato, y el código se lee como la fórmula matemática. Con -O2 el compilador elimina casi todas las copias: devolver structs no es «lento».

C · Bloque 5 — Cabeceras, guardas de inclusión y módulos (Tareas 2 y 3)

Ponemos cada tipo y sus funciones en su propia cabecera (vec3.h, ray.h, color.h) y main.c las junta con #include. Así crecen los programas en C sin volverse inmanejables.

Por qué importa

  • La guarda de inclusión (#ifndef / #define / #endif) evita que el archivo se procese dos veces si se incluye desde varios sitios (lo que daría errores de «redefinición»).
  • static inline permite definir las funciones dentro de la cabecera sin provocar errores de «símbolo duplicado» al enlazar.
  • Los archivos .h se incluyen, no se compilan aparte: solo compilamos main.c. (La compilación separada en varios .c llega en la Tarea 13.)
  • Como vec3.h usa sqrt, hay que enlazar libm con -lm al final de la orden de gcc.

C · Bloque 6 — Punteros, arrays, & y -> (Tarea 5)

Una función en C solo devuelve un valor. Pero al detectar un impacto queremos varios datos a la vez: el punto, la normal, la distancia t… La solución idiomática es la salida por parámetro: pasar un puntero a una estructura y que la función la rellene.

. frente a ->

Con una variable (o una copia) accedes al campo con el punto: temp.t. Con un puntero usas la flecha: rec->t, que es exactamente lo mismo que (*rec).t.

&, arrays y NULL

&temp es «la dirección de temp». El mundo es un array de sphere (un bloque contiguo) más un contador. NULL es un puntero «a nada» (aquí, un material aún sin asignar).

Traducción de C++ a C

El libro original usa una clase interval para el rango [t_min, t_max]. En C lo pasamos como dos parámetros double: menos maquinaria, mismo resultado.

Linux — La terminal, la redirección > y las tuberías |

Todo programa en la terminal tiene tres canales. Entenderlos es la clave de por qué la imagen y el progreso no se mezclan.

CanalNúmeroPara quéEn nuestro código
Entrada estándar (stdin)0Datos que entran al programa(no lo usamos aún)
Salida estándar (stdout)1El resultado «bueno»La imagen PPM: printf, write_color
Salida de error (stderr)2Mensajes, avisos, progresoEl progreso: fprintf(stderr, ...)

Redirección con >

El operador > desvía la salida estándar a un archivo (lo crea o lo sobrescribe). Por eso ./rt > imagen.ppm guarda la imagen en el archivo, pero el progreso sigue viéndose en pantalla: lo imprimimos por stderr, que > no toca. Si hubiéramos mandado el progreso por stdout, se habría colado dentro del .ppm y la imagen no abriría.

> archivo >> añade al final < archivo (entrada) 2> solo errores | tubería # comentario en shell

Tuberías con |

Una tubería conecta el stdout de un programa directamente con el stdin del siguiente, sin archivo intermedio. Así podemos convertir la imagen a PNG de un tirón, o encadenar comandos pequeños que hacen una cosa cada uno.

$ gcc -Wall -O2 main.c -o rt -lm      # compilar (libm con -lm, al final)
$ ./rt > imagen.ppm                  # stdout -> archivo; el progreso (stderr) sigue en pantalla
Filas restantes: 0
¡Listo!
$ ./rt | pnmtopng > imagen.png      # tubería: PPM directo a PNG, sin archivo intermedio
$ ./rt > imagen.ppm 2> avance.txt    # además, el progreso va a otro archivo
$ convert imagen.ppm imagen.png       # alternativa con ImageMagick

Física y matemáticas que debes reconocer

No entra materia nueva de física, pero sí debes saber leer estas fórmulas en el código:

Vectores

Producto escalar a·b = axbx + ayby + azbz, norma |a| = √(a·a), unitario a/|a|. (length_squared evita la raíz cuando solo comparamos longitudes.)

Rayo

Semirrecta P(t) = A + t·b: origen A (la cámara), dirección b, parámetro t. Con t>0 se avanza «hacia delante».

Cielo (lerp)

Interpolación lineal: color = (1−a)·blanco + a·azul, con a según la altura de la dirección del rayo.

Esfera y normal

Intersección: cuadrática a t² − 2h t + c = 0; el discriminante h² − a·c dice si hay impacto (≥0) o no (<0). Normal n = (P − C)/r.

Errores frecuentes (repásalos antes del examen)

  • División entera: i/(n-1) con enteros da 0. Usa (double)i/(n-1).
  • Olvidar -lm al usar sqrt/tan → error de enlazado «undefined reference to sqrt». Y debe ir al final.
  • Olvidar el ./ al ejecutar → «orden no encontrada».
  • Confundir . y ->: variable usa ., puntero usa ->.
  • = en vez de == dentro de un if: uno asigna, el otro compara.
  • Progreso por stdout: ensucia el .ppm y la imagen no abre. Va por stderr.
  • Falta un #include (<stdio.h> para printf, <math.h> para sqrt).
  • Sin guarda de inclusión → errores de «redefinición» al incluir una cabecera dos veces.

Autoevaluación — intenta responder antes de abrir

¿En qué se diferencia compilar de interpretar? ¿Cuántos pasos hay en C?

Interpretar ejecuta el código directamente (como Python). Compilar lo traduce antes a un ejecutable. En C hay dos pasos: compilar (gcc) y luego ejecutar (./rt).

¿Qué imprime printf("%d\n", 3/2);? ¿Cómo obtienes 1.5?

Imprime 1: 3 y 2 son enteros, así que hay división entera. Para obtener 1.5 usa un molde: (double)3/2 e imprime con %f.

¿Para qué sirve (double) en (double)i/(n-1)?

Convierte i a real antes de dividir, forzando una división real en vez de entera. Sin él, para i < n-1 el resultado sería 0.

¿Por qué el progreso se imprime por stderr y no por stdout?

Porque redirigimos stdout al archivo .ppm (./rt > imagen.ppm). Si el progreso fuera por stdout, se metería dentro de la imagen. Por stderr aparece en pantalla y no ensucia el archivo.

¿Qué hace ./rt > imagen.ppm? ¿Y ./rt | pnmtopng > imagen.png?

El primero guarda la salida estándar (la imagen) en imagen.ppm. El segundo usa una tubería: envía el PPM directamente a pnmtopng, que produce el PNG, sin crear el .ppm intermedio.

¿Por qué sqrt necesita -lm y dónde va la bandera?

Las funciones matemáticas están en la biblioteca libm, que hay que enlazar explícitamente con -lm. Va al final de la orden de gcc.

¿Qué es una guarda de inclusión y qué problema evita?

El bloque #ifndef X / #define X / ... / #endif. Evita que una cabecera se procese dos veces cuando se incluye desde varios sitios, lo que causaría errores de «redefinición».

Diferencia entre . y ->. ¿A qué equivale rec->t?

Con una variable/copia se usa el punto (temp.t); con un puntero, la flecha (rec->t). rec->t equivale a (*rec).t.

En C89 no hay bool. ¿Cómo se representa verdadero/falso?

Con un int: 0 es falso y cualquier otro valor es verdadero. Desde C99 existe <stdbool.h> con bool/true/false.

Una función solo devuelve un valor. ¿Cómo entregamos punto, normal y t a la vez?

Con salida por parámetro: pasamos un puntero a un hit_record (hit_record *rec) y la función lo rellena; el return queda para el int «¿hubo impacto?». Al llamar pasamos &temp.
