cron: tareas programadas

Objetivo

Programar órdenes para que se ejecuten solas a horas fijas (cada noche, cada lunes, cada 5 minutos) con cron, y aprender a depurarlas cuando «no hacen nada».

Concepto · el demonio cron y la crontab

cron es un programa que se ejecuta permanentemente en segundo plano (un demonio) y, cada minuto, mira si hay alguna tarea programada. Cada usuario tiene su propia tabla de tareas, la crontab, que se edita con crontab -e y se consulta con crontab -l.

Formato de una línea

Cinco campos de tiempo y, después, la orden:

archivo · crontab
# ┌───────── minuto        (0-59)
# │ ┌─────── hora          (0-23)
# │ │ ┌───── día del mes   (1-31)
# │ │ │ ┌─── mes           (1-12)
# │ │ │ │ ┌─ día de semana (0-7; 0 y 7 = domingo)
# │ │ │ │ │
  30 2 * * *  /home/ana/rt/render_nocturno.sh

Un * significa «cualquier valor». Esta línea ejecuta el script todos los días a las 02:30.

LíneaCuándo se ejecuta
*/5 * * * *cada 5 minutos
0 * * * *al principio de cada hora
30 2 * * *todos los días a las 02:30
0 9 * * 1-5de lunes a viernes a las 09:00
0 0 1 * *el día 1 de cada mes a medianoche
15,45 8-18 * * *a y cuarto y a menos cuarto, de 8 a 18 h
@rebootuna vez, al arrancar el ordenador
@dailyuna vez al día (equivale a 0 0 * * *)

Un ejemplo completo: render nocturno

El render final en alta resolución tarda más de una hora. Lo programamos para la noche con un script que usa todo lo aprendido: redirección, permisos y (para el informe) grep y awk.

archivo · render_nocturno.sh
#!/bin/bash
# Render nocturno: compila, renderiza y registra el resultado.
cd /home/ana/rt || exit 1             # cron arranca en $HOME: vamos al proyecto
FECHA=$(date +%F)                     # p. ej. 2026-11-20

gcc -Wall -O2 src/*.c -o rt -lm || exit 1
inicio=$(date +%s)
./rt > "renders/final-$FECHA.ppm" 2> /dev/null
fin=$(date +%s)

echo "$FECHA render terminado en $((fin - inicio)) s" >> renders/historial.txt
terminal
$ chmod +x render_nocturno.sh      # ¡imprescindible! (tema 3)
$ ./render_nocturno.sh               # pruébalo a mano ANTES de programarlo
$ crontab -e                         # se abre un editor; añade esta línea:
30 2 * * * /home/ana/rt/render_nocturno.sh >> /home/ana/rt/cron.log 2>&1
$ crontab -l                         # comprueba que quedó guardada

Pista · «mi tarea de cron no hace nada»

Es el problema más habitual. Casi siempre es una de estas causas:

  • Entorno distinto. cron ejecuta con un PATH mínimo y desde tu directorio personal. Usa rutas absolutas para todo, o haz cd al principio del script.
  • Sin permiso de ejecución. Comprueba ls -l del script.
  • La salida se pierde. No hay terminal: redirige stdout y stderr a un fichero (>> cron.log 2>&1) para poder ver los errores.
  • El % es especial en la crontab: escríbelo como \%, o mejor, mete la orden en un script.
  • cron no está en marcha. Compruébalo con systemctl status cron. En WSL no se arranca solo: sudo service cron start.

Un primer ejercicio, de un minuto

terminal
$ crontab -e                               # añade la línea de abajo: cada minuto
* * * * * date >> /tmp/latido.txt
$ tail -f /tmp/latido.txt                  # observa cómo crece (Ctrl+C para salir)
vie 20 nov 2026 10:41:01 -03
vie 20 nov 2026 10:42:01 -03
$ crontab -e                               # ...y BORRA la línea al terminar

Ordenadores compartidos

En los ordenadores del laboratorio piensa antes de programar tareas pesadas: un render cada 5 minutos ocupará la máquina de otros. Para lanzar una sola vez algo largo que sobreviva a cerrar la sesión, es más adecuado nohup ./rt > imagen.ppm 2> progreso.txt &.

Ejercicios

  • Programa la tarea «latido» de cada minuto, comprueba que funciona con tail -f y después elimínala. ¿Qué muestra crontab -l al final?
  • Escribe la línea de crontab que ejecutaría ~/rt/render_nocturno.sh a las 23:00 los viernes, y otra para cada 15 minutos entre las 9 y las 17 h.
  • Crea un script informe.sh que, a partir de render.log, escriba en informe.txt cuántos errores y avisos hubo y el tiempo total de render (combina grep -c, awk y >>). Prográmalo con cron y comprueba el resultado.
