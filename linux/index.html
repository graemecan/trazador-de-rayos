La terminal como laboratorio

Ya usas la terminal para compilar con gcc y ejecutar ./rt > imagen.ppm. Este módulo corto explica qué hay detrás de ese > y presenta las herramientas clásicas de Unix para encadenar programas, proteger ficheros, buscar y transformar texto, y programar tareas que se ejecutan solas.

Sistema: Linux / WSL / macOS Shell: bash 7 temas cortos

La filosofía Unix

Las herramientas de Unix siguen una idea sencilla: cada programa hace una sola cosa, y la hace bien; los programas leen y escriben texto, de modo que la salida de uno puede ser la entrada de otro. Con media docena de órdenes pequeñas —grep, sort, sed, awk…— y la forma de conectarlas (|, >) se resuelven en una línea problemas que en C costarían un programa entero.

Para un físico esto es muy práctico: los datos de laboratorio, las salidas de simulaciones y los registros (logs) de un programa como nuestro trazador de rayos son, casi siempre, ficheros de texto organizados en líneas y columnas.

Cómo leer los ejemplos

Las líneas que empiezan por $ son órdenes que escribes tú (sin el $). Lo que aparece debajo es la salida. Lo que va tras # es un comentario: la shell lo ignora.

Ficheros de práctica

Todos los temas usan dos ficheros pequeños: unas medidas de laboratorio en formato CSV y el registro de varias ejecuciones del trazador de rayos. Créalos copiando y pegando este bloque en una terminal (la construcción <<'EOF' se explica en el tema 1):

$ mkdir -p ~/practica-linux && cd ~/practica-linux

luis,pendulo,1.98,21.7
marta,muelle,0.85,22.0
ana,muelle,0.87,22.1
pedro,pendulo,2.05,21.4
luis,caida,0.45,21.9
marta,pendulo,2.00,21.6
pedro,caida,0.47,22.3
EOF
$ cat > render.log <<'EOF'
